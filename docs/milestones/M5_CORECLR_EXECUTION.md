# M5 CoreCLR Execution

## Outcome

Text-authored and visually authored programs compile to and execute as the same
validated CoreCLR method body, retaining semantic identity for future engine
and debugger integration.

## M5.1 implemented vertical slice

- new `UnifiedScript.Runtime` project separating invocation/result contracts
  from Roslyn, Graph, CLI, and future UE adapters
- deterministic in-memory PE plus portable-PDB emission after Visual Profile,
  compiler, semantic, Graph, and CFG validation
- strict `unifiedscript.execution-result/v0.1` returned/faulted schema carrying
  compilation, configuration, and method IDs
- stable semantic-method-ID invocation with qualified-name resolution only at
  the CLI boundary
- exact JSON conversion for graph-safe scalar, enum, array, enumerable, and
  list arguments; canonical scalar and enum return encoding
- synchronous static `[Visual]` entry-point boundary with explicit rejection of
  instance and async entry points
- target exception unwrapping into deterministic type/message faults
- collectible assembly load context, shared dependency resolution, explicit
  disposal, and a GC-proven unload test after source-defined enum execution
- `execute` CLI command with returned value, structured fault, compilation
  failure, and invocation-error exit semantics
- checked-in enumerable execution sample and an automated text-authored versus
  visual-plan-authored result-equivalence proof

## M5.1 acceptance criteria

1. Invalid profile or semantic programs never produce a PE image.
2. Identical requests emit byte-identical PE and portable PDB hashes.
3. Emission revalidates Graph and derived CFG before loading executable code.
4. A CLI-qualified Visual method resolves to its existing semantic method ID.
5. Invocation checks Visual/static/synchronous shape, argument count, and exact
   JSON conversion before calling reflection.
6. Scalar, enum, array, and enumerable arguments cross the backend-neutral
   boundary without exposing CLR reflection objects.
7. Successful scalar/enum returns use canonical JSON plus semantic type name.
8. Target exceptions become structured faults without
   `TargetInvocationException` leakage.
9. Returned/faulted JSON strictly validates schema and mutually exclusive
   payloads.
10. Disposing a session releases its collectible load context after no results
    retain source-assembly objects.
11. The public CLI executes both returned and faulted sample paths with stable
    output and exit status.
12. A real checked-in visual patch plan and an independently text-authored
    equivalent method return the same typed value through the same host.
13. Runtime boundaries and the absence of a security sandbox are documented.
14. The full solution, 313-test suite, format check, repository validator, and
    execution CLI regressions pass.

## M5.2 implemented source-map slice

- strict `unifiedscript.source-map/v0.1` schema retaining assembly,
  compilation, and semantic-configuration identity
- exact semantic method ID to CLR MethodDef metadata-token mapping
- executable HIR statement/expression ID to one-or-more IL-offset mapping
- visible portable-PDB sequence-point table with normalized logical paths and
  one-based source spans
- CLR signature matching for same-arity overloads, nullable value types, and
  nullable-reference metadata erasure
- deterministic normalization and rejection of duplicate methods/tokens/nodes,
  invalid spans, and dangling IL offsets
- immutable source-map exposure from both program images and collectible
  execution sessions
- `emit` and `emit-files` CLI commands producing DLL, PDB, and source-map JSON
- visual foreach plan verification proving the generated loop ID has a real IL
  location before execution
- explicit empty kickoff-method mapping for async methods until state-machine
  execution and debugging are supported

## M5.2 acceptance criteria

1. Every synchronous Visual method resolves to exactly one emitted MethodDef.
2. Every published node IL offset exists in the same method's PDB sequence
   points.
3. Same-arity overloads resolve by exact CLR signature rather than declaration
   order.
4. Nullable value and reference signatures survive CLR representation changes.
5. Identical requests produce canonical-identical source-map JSON in addition
   to byte-identical PE/PDB images.
6. Old schemas, duplicate identities, invalid spans, and dangling offsets are
   rejected during serialization and deserialization.
7. A node generated by a checked-in visual patch plan appears in the emitted
   source map with at least one IL offset.
8. The public CLI emits a loadable DLL, portable PDB, and validated source map
   as one program-image artifact set.
9. The full solution, 318-test suite, format check, repository validator,
   source-map CLI, nullable-signature, and execution regressions pass.

## M5.3 implemented reload/debug-protocol slice

- deterministic request fingerprints plus `sha256:` PE/PDB/source-map image
  content addresses
- thread-safe bounded LRU cache with hit/miss statistics that retains only
  successfully emitted images
- domain-scoped monotonic reload numbers and distinct semantic generation IDs
- cached-image reload into a fresh collectible context without recompilation
- transactional reload failure preserving the previous session and bindings
- reconciled identity-sidecar propagation through images, reload results, and
  transactional CLI emission
- strict breakpoint binding, hit, and resolution JSON v0.1 protocols
- bound/pending/disabled semantic breakpoint states with multi-offset locations
- automatic persistent-node rebind, deletion-to-pending migration, and
  pending-to-bound restoration
- domain/generation/image-key stale-hit rejection with stable `UDB1002`
- exact current-hit reverse mapping to semantic method/breakpoint/node IDs
- disposal of superseded collectible contexts and permanent domain closure

## M5.3 acceptance criteria

1. Repeating an identical request skips emission and returns the same image
   content address.
2. Every successful load receives a higher generation number and distinct
   generation ID, including cached-image reloads.
3. Formatting changes preserve sidecar-backed breakpoint node IDs while
   rebinding their new PDB/IL locations.
4. Deleted nodes become tombstones and pending breakpoints; reappearing nodes
   automatically bind again.
5. A failed compilation leaves the previous generation executable and its
   breakpoint snapshot unchanged.
6. Hits must match domain ID, generation ID, image key, MethodDef token, and IL
   offset before semantic resolution.
7. Hits from superseded generations fail with `UDB1002`; unbound locations fail
   with `UDB1003`.
8. DLL, PDB, source map, and updated identity sidecars emit transactionally.
9. Superseded collectible contexts unload, and disposed domains cannot reload.
10. The full solution, 331-test suite, formatting, repository validation,
    cache/reload, breakpoint JSON, identity migration, CLI, and execution gates
    pass.

## M5.4 implemented live-debug-adapter slice

- post-validation debug instrumentation that preserves original HIR, semantic,
  source-map, and sidecar identity and still executes Roslyn-emitted CoreCLR IL
- statement-node probe installation with honest `Pending` expression
  breakpoint behavior
- actual execution-thread suspension rather than post-execution hit simulation
- cooperative pause-at-next-probe, continue, and call-depth-aware step-over
- deeper-call breakpoint precedence while stepping over a call
- live CoreCLR stack frames reduced to detached method/token/offset/source data
- Roslyn-definitely-assigned top-frame parameters and locals
- bounded depth/width value trees using public fields only, with explicit cycle,
  truncation, and unavailable states and no collectible-object leakage
- strict generation, execution, and pause lifetime checks with stable `UDB`
  failures
- `ICoreClrDebugTransport` plus an in-process loopback implementation suitable
  for editor integration and later backend replacement
- running/suspended reload rejection and completed-generation stale-command
  rejection

## M5.4 acceptance criteria

1. Debug instrumentation runs only after every normal validation gate and does
   not become part of HIR or Graph identity.
2. A breakpoint event is published while the CoreCLR invocation task is still
   incomplete and the execution thread remains blocked.
3. Continue releases the exact current pause; resumed or unknown pauses are
   rejected.
4. Step-over ignores probes in a deeper called Visual method and stops at the
   next same/shallower frame, while an explicit nested breakpoint still wins.
5. A nested breakpoint exposes the actual two-frame managed stack.
6. Top-frame locals contain only parameters and locals definitely assigned at
   the statement entry.
7. Local values retain no source objects or reflection metadata and bound
   arrays/objects by depth and width while detecting cycles.
8. Expression breakpoints remain explicitly pending rather than moving to a
   nearby statement.
9. Reload is rejected while running/suspended; commands using a completed old
   generation fail with `UDB1002` after reload.
10. Normal emission retains its single-emission path and existing deterministic
    image/source-map behavior.
11. The full solution, 337-test suite, formatting, repository validation,
    execution/source-map/reload regressions, and live debug tests pass.

## Next slice

Runtime expansion pauses for the M5.5 Script Asset and Authoring Experience
slice. The current method-body Graph omits type-level state/default/exposure
declarations, so proceeding directly to async/native-debug or UE binding would
leave a Blueprint-only authoring dependency. M5.5 adds Declaration IR and
connects a non-spaghetti Structure/Split/Code editor to real artifacts. See
[M5_5_AUTHORING_EXPERIENCE.md](M5_5_AUTHORING_EXPERIENCE.md) and
[VISUAL_AUTHORING_MODEL.md](../VISUAL_AUTHORING_MODEL.md).

Native managed debugging and async/cancellation remain subsequent runtime
tracks behind the already established `ICoreClrDebugTransport` and execution
contracts.
