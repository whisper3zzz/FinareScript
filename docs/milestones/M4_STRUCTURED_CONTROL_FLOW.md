# M4: Structured Control Flow Expansion

## Goal

Make practical gameplay control flow explicit, verifiable, and editable in the
shared Graph/HIR model before introducing a UE editor or a second execution
path.

Status: in progress. M4.1 explicit regions, M4.2 derived CFG analysis, M4.3
CFG-checked local assignment/data reconnection, M4.4 recursive nested branch
construction, M4.5 structured loop projection/analysis, and M4.6 bounded
Graph-authored loop construction are implemented. M4.7 adds exact typed editing
of assignment values and existing or plan-produced while conditions. M4.8
generalizes exact endpoint editing to local initializers, if conditions, and
return values on both existing and plan-produced statements. M4.9 lets later
typed expression trees consume locals generated by earlier plan stages. M4.10
replaces one exact nested Graph input while preserving its enclosing expression
spine. M4.11 publishes real roots for plan-authored expressions and lets later
stages traverse and edit them through chainable structural port handles. M4.12
through M4.14 establish first-class conditional, short-circuit logical, and
null-coalescing lazy expressions. M4.15 preserves null-conditional access and
its implicit receiver as an explicit shared-VM contract.

## M4.1 implemented vertical slice

- `unifiedscript.graph/v0.3` schema
- explicit `GraphRegionKind` values for `function`, `block`, `if`, `then`, and
  `else`

- exactly one direct region owner for every Graph node
- source HIR owner and source span on every region
- explicit vs implicit `else` preservation
- stable region IDs derived from persistent HIR IDs and structural roles
- region-aware projection for expressions, effects, branches, early returns,
  and nested lexical blocks
- deterministic Graph JSON normalization and region validation
- Graph-layout compatibility without mixing semantic and comment regions

## M4.1 acceptance criteria

1. A method projects a `function` root with exactly one body `block` child.
2. Every node appears in exactly one region's `nodeIds`.
3. An `if` directly owns its condition and branch node.
4. Each `if` owns ordered `then` and `else` children.
5. A missing C# `else` becomes an empty implicit region; an explicit empty
   `else` remains non-implicit.
6. Early-return nodes belong to the selected branch while the outer fallback
   remains in the surrounding block.
7. Nested lexical blocks form child block regions.
8. Invalid ownership, hierarchy, branch order, or implicit markers fail JSON
   validation.
9. Identical input produces byte-identical region-aware Graph JSON.
10. Existing semantic node layout survives region projection unchanged.
11. The CLI emits and consumes the current region-aware Graph schema for layout
    initialization/sync.
12. The full solution, project validator, Golden fixture, and CLI regressions

## Deliberate limits

M4 consumes derived CFG facts at patch time but does not serialize them or
materialize source/Graph merge nodes. Assignment editing is limited to the
right-hand value of a root simple assignment to an existing local; it cannot
retarget the write, synthesize declarations with arbitrary initializers, write
members/indexers, or support compound assignment, increment/decrement, calls,
or effectful right-hand sides. Existing if/while conditions, local initializers,
and value returns support whole-endpoint replacement. Existing binary,
bounded-unary, cast, conditional, conditional-access receiver, and
positional-invocation argument inputs support exact nested replacement.
Generated expression roots now publish transaction-local handles with bounded
binary/unary/cast/conditional/conditional-receiver paths. Authored
expressions can reference existing same-method definitions and locals produced
earlier in one plan. Produced paths do not yet traverse ordinary members,
conditional selected bindings, calls, assignments, awaits, or wildcard/parent
queries. Branch and loop-body insertions append and cannot move or delete
existing structures. Loop transfers cannot be retargeted.
Existing-`for` whole-clause restructuring remains unavailable beyond M4.18's
exact condition/declaration-initializer/assignment-value/incrementor endpoints.
Pattern-only or ambiguous enumerators, conditional disposal, ref/async
`foreach`, switch,
conditional element access,
conditional effect subgraphs for lazy expression inputs, exception edges,
standalone short-circuit CFG regions, async state-machine transitions, control
dependence, SSA, and automatic node placement remain outside the current slice.
