# M4: Structured Control Flow Expansion

## Goal

Make practical gameplay control flow explicit, verifiable, and editable in the
shared Graph/HIR model before introducing a UE editor or a second execution
path.

Status: in progress. M4.1 explicit regions, M4.2 derived CFG analysis, M4.3
CFG-checked local assignment/data reconnection, M4.4 recursive nested branch
construction, M4.5 structured loop projection/analysis, and M4.6 bounded
Graph-authored loop construction are implemented. M4.7 adds exact typed editing
of assignment values and existing or plan-produced while conditions. M4.8
generalizes exact endpoint editing to local initializers, if conditions, and
return values on both existing and plan-produced statements. M4.9 lets later
typed expression trees consume locals generated by earlier plan stages. M4.10
replaces one exact nested Graph input while preserving its enclosing expression
spine.

- `unifiedscript.graph/v0.3` schema

## Deliberate limits

M4 consumes derived CFG facts at patch time but does not serialize them or
materialize source/Graph merge nodes. Assignment editing is limited to the
right-hand value of a root simple assignment to an existing local; it cannot
retarget the write, synthesize declarations with arbitrary initializers, write
members/indexers, or support compound assignment, increment/decrement, calls,
or effectful right-hand sides. Existing if/while conditions, local initializers,
and value returns support whole-endpoint replacement. Existing binary,
bounded-unary, cast, and positional-invocation argument inputs support exact
nested replacement, but generated arbitrary expression nodes do not yet
publish symbolic node/port handles. Authored
expressions can reference existing same-method definitions and locals produced
earlier in one plan, but arbitrary generated expression results do not publish
handles. Branch and loop-body insertions append and cannot move or delete
existing structures. Loop transfers cannot be retargeted.
`do`/`for`/`foreach`, switch, conditional expressions, exception edges,
short-circuit expression flow, async state-machine transitions, control
dependence, SSA, and automatic node placement remain outside the current slice.

## Next slice

M4.11 should publish stable transaction handles for arbitrary expression nodes
created by earlier plan stages, allowing a later input edit to target a
generated parent without predicting its persistent ID. It should retain the
same old-endpoint, type, effect, evaluation-order, scope, dominance, trivia,
and unaffected-spine identity proofs. `for` and `foreach` still need an
explicit lossless HIR decision before admission rather than silently
desugaring source syntax into while loops.
